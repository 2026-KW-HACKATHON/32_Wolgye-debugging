# 32_Wolgye-debugging

2026 KW HACKATHON 32조 — **빌라 주차 스택 관리 앱**

좁은 골목 빌라의 종렬(앞뒤로 겹치는) 주차에서, 각자 예상 출차 시간을 공유해
"내가 나갈 때 앞차가 막지 않는 자리"를 고르게 해주는 지역 한정 앱입니다.

## 문제

- 빌라 주차장은 앞차가 빠져야 뒤차가 나올 수 있는 LIFO 스택 구조입니다.
- 주차장법상 5대 이하 주차장은 세로 2대 배치가 허용되어 구조 자체는 합법이지만, "누가 언제 나가는지" 공유할 방법이 없어 전화로 차를 빼달라고 요청하다 갈등이 반복됩니다.
- 기존 서비스(모두의주차장 등)는 빈 **공간**을 공유하지만, 우리는 **출차 시간**을 공유합니다.

## 서비스 범위

- 지역: 서울 노원구 월계1동, 그중에서도 좁은 골목의 빌라 부설주차장(사유지)를 목표로 합니다.
- 노상(골목) 주차는 다루지 않습니다. 불법이며 소방 진입로 문제와 얽혀 있습니다.

## 타깃

- 좁은 주차장에 이중주차하는 빌라 차주
- 자리가 남는 빌라의 건물주·관리인 (공간 제공)

## 조사로 확인한 문제

월계1동 빌라는 세대당 주차면이 **0.40대**(2,468세대, 986면)라 이중주차가 불가피합니다.
노원구 주택가 주차장 확보율은 아파트를 포함하면 103.6%지만 공동주택을 빼면 **63.6%**로, 빌라촌의 부족은 통계에 가려져 있습니다.

| 조사 | 결과 |
| --- | --- |
| 현장 설문 (유효 15명) | 차량 소유자 6명 중 **5명**이 최근 한 달 새 막힌 경험 |
| 현장 설문 (시간대 응답 5명) | **5명 전원** 이른 아침(6~9시) |
| 현장 설문 (최다 불편) | 대기가 아닌 이른 아침·늦은 밤 **연락의 미안함** (3명) |
| 현장 설문 (차량 비소유 6명) | 골목 통행 불편 경험 4명 |
| 인터뷰 | 전화를 받지 않아 초인종을 누르거나, 옆 빌라에 댔다가 관리인과 다툰 경험. 정작 옆 빌라 자리는 비어 있다는 증언 |

## 솔루션

골목 빌라끼리 **빈자리와 출차 시간을 공유**하는 주차 서비스입니다.

- **빈자리 공유**: 남는 자리를 시간제 유료로 열어 이웃 빌라 주민이 사용 (자리 부족 해소)
- **주차 현황 확인·자리 추천·출차 예약**: 이웃의 출차 시간을 확인하고, 이웃과 나의 출차 위치를 고려한 최적의 자리를 추천하며, 나를 막을 차주에게 전날 밤 알림 (막힘 감소)
- **원탭 출차 요청**: 안심번호·정중한 문구 사용, 출차 정보는 같은 빌라만 열람 (미안함·방범 우려 해소)

> 위 솔루션은 서비스 전체 비전이며, 해커톤 개발 범위는 아래 [주요 기능 (MVP)](#주요-기능-mvp)를 기준으로 합니다.

## 차별성

- **사후 대응 → 사전 예방**: 빌라 관리 앱 'Capl'이 막힌 뒤의 알림·연락을 돕는다면, 우리 서비스는 출차 시간을 미리 모아 자리 추천·전날 밤 알림으로 막힘 자체를 줄입니다. 막힘이 몰리는 이른 아침(현장 설문 시간대 응답 5명 전원)을 겨냥했습니다.
- **출차 기록이 곧 공유 근거**: '모두의주차장'은 소유자가 시간을 정해 판매하지만, 우리는 쌓인 출차 기록으로 '언제 비는지'를 보여 줍니다. 온라인 설문(53명)에서 공유 주차 이용 시 '예약 시간에 자리가 확실히 비는지'를 중요하게 꼽은 응답이 **25명**이었습니다.
- **낯선 외부인이 아닌 골목 이웃**: 인증된 이웃에게만 열고 안심번호로 연락해 방범·개인정보 우려와 빌라 간 다툼에 답합니다. 같은 온라인 설문에서 '소유자 허락과 이용 권한 확인'을 중요하게 꼽은 응답도 **17명**이었습니다.
- **주차장 안 자리까지 안내**: 지도·로드뷰로 주차장까지 안내하는 '모두의주차장'과 달리, 배치도로 처음 가는 빌라 주차장의 자리와 진입 경로까지 보여 줍니다. (온라인 설문: 진입 공간 19명, 정확한 위치 14명이 중요하다고 응답)

## 기대효과

- **입주민**: 새벽 전화·초인종 없는 출차, 아침 출차 지연·연락 부담 감소, 이웃 갈등 예방
- **건물주·관리인**: 입주민 이용 시간은 지키며 빈자리 수익, 주차 민원 감소
- **지역**: 새 주차장 없이 기존 빌라 주차면 986면 활용도 제고, 골목 통행 불편 완화, 다른 빌라촌으로 확장

## 핵심 아이디어

- 주차장은 여러 개의 lane(열)으로 이루어지고, 각 lane은 스택입니다. (position 0이 가장 안쪽)
- **불변식**: 안쪽으로 갈수록 예상 출차 시간이 늦어야 합니다.
- **입차 안전 판정**: 내 예상 출차 시간이 해당 lane 맨 바깥 차의 예상 출차 시간 이하이면 안전합니다.
- **lane 추천**: 안전한 lane 중 맨 바깥 차와 출차 시간 차이가 가장 작은 lane을 추천합니다. 여유가 큰 lane을 아껴 나중에 늦게 나가는 차를 받기 위함입니다.
- **동시성**: 같은 lane에 동시 입차 시 순서가 꼬이지 않도록 lane 단위 잠금 트랜잭션으로 처리합니다.

## 주요 기능 (MVP)

1. 빌라 초대코드로 가입 (건물 단위 신뢰 확보)
2. 주차장 레이아웃 화면: 위에서 내려다보는 2D 뷰, 칸마다 상태 색상 표시
3. 입차 등록: 칸 선택 + 예상 출차 시간 입력
4. 자리 추천: 안전한 칸 표시, 막히는 칸 경고
5. 알림: 앞차 출차 임박, 내 차가 남을 막고 있음, 이동 요청 수신
6. 이동 요청: 전화번호 노출 없이 앱 내에서 "차 빼주세요" 전송
7. 미등록 차량: "출차 시간 미상" 차량으로 칸에 등록

### 확장 기능 (여유가 있으면)

- 인근 여유 빌라의 유휴 주차면 유료 대여 (건물 소유자/관리자가 등록하는 흐름만 허용)
- 출차 시간 준수율 기반 신뢰도 표시

## 제약 / 원칙

- API 키를 앱에 하드코딩하지 않으며, LLM 호출은 백엔드를 경유합니다.
- 로드뷰 이미지를 저장하거나 가공하지 않습니다 (지도사 약관 위반 소지).
- GPS로는 칸 판별이 불가능(오차 5~10m)하므로 칸 확정은 사용자가 직접 선택합니다.
- 차량번호는 마스킹해서 저장/표시하고(예: `12가 ****`), 전화번호는 노출하지 않습니다.
- 3D 모델링, 실결제, 마이크로서비스는 범위 밖입니다.
